# دمو آنلاین با فرانت‌اند و بک‌اند

پیشنهاد این پروژه: **فرانت روی Vercel، API مستقل روی Render و دیتابیس روی MongoDB Atlas**. درخواست مرورگر به `/api` همان دامنه وب می‌رود و Next.js آن را به API می‌فرستد؛ این مسیر دردسر کوکی‌های بین دو سایت را کمتر می‌کند.

Vercel فقط فرانت‌اند نیست؛ نمونه‌های رسمی Node.js و Express هم دارد. اجرای بک‌اند در آن به مدل Functions و محدودیت‌های زمان اجرا و اتصال دیتابیس وابسته است. برای حفظ معماری دو اپ مستقلِ درخواستی، این پروژه فعلاً میزبان Node جدا را هدف گرفته است.

فایل `render.yaml` برای API و راهنمای گام‌به‌گام انگلیسی در `deployment.md` آماده است. مراحل اصلی:

1. دیتابیس Atlas بسازید، کاربر اختصاصی ایجاد کنید و دسترسی شبکه میزبان API را تنظیم کنید.
2. ریپازیتوری را در Render وارد کنید؛ مقادیر خصوصی دیتابیس، JWT، ایمیل و دامنه نهایی فرانت را در تنظیمات همان سرویس قرار دهید.
3. همان ریپازیتوری را در Vercel با ریشه `apps/web` وارد کنید. `API_URL` را روی آدرس API و `NEXT_PUBLIC_SITE_URL` را روی دامنه وب تنظیم کنید.
4. مقدار `WEB_URL` بک‌اند باید دقیقاً برابر دامنه نهایی فرانت باشد. پس از تغییر `API_URL`، وب را دوباره build کنید.
5. ثبت‌نام، تأیید ایمیل، ذخیره تسک/یادداشت و کوکی‌ها را روی دامنه واقعی تست کنید. AI اختیاری است و کلید فقط روی بک‌اند تنظیم می‌شود.

برای ایمیل، هم SMTP با Nodemailer و هم Resend از مسیر HTTPS پشتیبانی شده است. گزینه HTTPS برای میزبان‌هایی که پورت SMTP را محدود می‌کنند مفید است. فرستنده باید واقعاً در سرویس ایمیل تأیید شده باشد. بدون تنظیم ایمیل، نسخه production عمداً شروع نمی‌شود تا بازیابی رمز و دعوت اعضا ظاهری نباشد.

نمونه رسمی Render استفاده از `plan: free` را نشان می‌دهد، اما سقف‌های فعلی پلن، خواب سرویس، مجوز استفاده و محدودیت‌های شبکه از صفحات زنده قابل بررسی نبودند؛ دسترسی محیط به آن صفحات مسدود بود. بنابراین رایگان و همیشه‌روشن بودن دمو تضمین نشده است. لینک مستندات رسمی در راهنمای انگلیسی آمده تا پیش از انتخاب پلن بررسی شوند. هزینه AI هم مستقل از هاست است.

در این جلسه ابزاری برای انتشار در **Sites** در دسترس نبود. صرف وجود بخش Sites ثابت نمی‌کند اجرای Express مستقل، متغیرهای خصوصی، اتصال Atlas و پاسخ استریم را پشتیبانی می‌کند. هنوز حساب میزبانی یا دمو عمومی ایجاد نشده است و نباید پوش Git را با انتشار سایت یکی بدانیم.

برای تست کامل در همین محیط ابری، دامنه `fastdl.mongodb.org` باید در تنظیمات شبکه فعال شود. سپس می‌توان MongoDB واقعی محلی را بدون Docker اجرا کرد و تست‌های دیتابیس و سفر کاربر را کامل انجام داد. داده ساختگی جای دیتابیس استفاده نشده است.
